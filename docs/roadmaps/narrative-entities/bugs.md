# Bugs y ajustes de entidades narrativas

## Pendientes

- Verificar a mano el flujo completo de `PATCH` y de la desasociación por libro de las entidades narrativas (el backend ya los tiene; en la web, «Quitar del libro» solo está en la tarjeta de detalle, que no se alcanza: `docs/roadmaps/ecosistema/ESPECIFICACION_elementos-narrativos.md`, §8.3).
- Ajustar el resto de inserciones narrativas entidad a entidad cuando se validen sus campos específicos.

## Resueltos

- [x] Rediseños de la APK llevados a la Web (6/11/2026): escenas plegadas, reparto con los iconos «en escena» y «solo nombrado», @ en el texto del editor RTF y «Tu lectura» en casillas. Lógica en `shared/scene-cast.ts`, `shared/rtf/mentions.ts` y `shared/reading-panel.ts`, con las pruebas de la APK portadas. Reglas visuales en `docs/GUIA_ESTILOS.md`.
- [x] Ficha de personaje (25/10/2026): las relaciones se guardan y borran por `RelacionId` (con `Id` de reserva; en la API, `Id` es el personaje relacionado), y quitar el chip del nombre actual ya no pide borrar ese apodo (`409 nickname_used_as_contextual_name`).
- [x] Alta de personajes (24/10/2026, producción: loader sin fin, lista sin el personaje y duplicado): el personaje entra en la lista en cuanto la API confirma el alta (`BookStoreService.upsertCharacter`); estado, relaciones y apodos se guardan después, cada paso con 30 s como máximo, sin recargar el libro; `finalize` retira siempre el loader; el envío se bloquea mientras guarda y lleva `IdCliente` (`shared/client-request-id.ts`), que se conserva en los reintentos; la lista se contrasta con `GET /libros/{id}/personajes/orden`; un nombre repetido pide confirmación. Se eligió la idempotencia por `IdCliente` y no rechazar nombres repetidos porque hay personajes legítimos con el mismo nombre en una saga. API `045cb6d`; prueba `e2e/web-character-creation.spec.ts`.
- [x] Nombres, participantes y estados de localización en sagas (24/10/2026, producción): la API aplica un criterio único de visibilidad por libro de creación, da nombre de reserva y `Nombre` en las filas de participantes, estado contextual con el nombre del catálogo e ids enteros (`51eb330`..`dc1e399`). La web compara ids como números y usa el `Nombre` de la fila antes de la etiqueta de reserva (`shared/narrative-entity-names.ts`). Se eligió nombrar con la API en vez de ocultar filas ausentes: ocultarlas escondería datos si las listas vuelven a divergir.
- [x] Escenas y capítulos: «Nueva escena» y «Nueva entrada» solo se admiten si todos los bloques existentes son válidos (una escena, con título, descripción, localización y al menos un personaje presente o nombrado; el backend lo acepta). La escena sin personajes solo vale al crear un capítulo y no se envía. Las partes admiten final abierto (`OrdenFinal = 0`). Pedir otro capítulo desde el alta cierra el índice y abandona la ruta bajo su guard para crear una instancia limpia.
- [x] Autoguardado del capítulo: solo confirma lo enviado y mantiene pendiente lo escrito durante una petición en vuelo; solo envía capítulos o escenas con cambios reales; aplica la respuesta (`Scene`) sobre el estado local sin recargar el libro; `PersonajesOrdenados` es una lista ligera de orden y el orden se refresca en segundo plano desde `/libros/{id}/personajes/orden`. Guarda también al abandonar capítulos y fichas.
- [x] RTF: lector y escritor con grupos, CP-1252, Unicode, fuentes, colores y propiedades de párrafo compatibles con RichTextBox; los párrafos vacíos iniciales o finales se conservan con `data-rtf-*`; harness RichEdit aislado (`qa/winforms-rtf-harness/`) con fixtures sintéticos y lector SQL de solo lectura. Las keywords narrativas son tokens no editables, con borrado atómico, sin corrector y con formato canónico de escritorio, y un debounce de 250 ms. La selección se restaura al usar controles de formato que abren paneles propios.
- [x] Entidades: cada entrada nueva empieza con «Descripción de…» en RTF y la autoselecciona al primer foco mientras siga intacta; el cambio de nombre de personaje tiene el modo narrativo por defecto (el nombre anterior queda como apodo) y uno de corrección de errata; el estado por libro del alta es un upsert idempotente; el regreso desde las rutas singulares de alta lleva a su listado plural.
- [x] Autocompletes de localización de escena, evento y personaje de cita: buscables, con ids normalizados a número, nombre canónico y «Sin localización» primero; el texto libre de localización no vale.
- [x] Asignaciones de personajes ordenadas alfabéticamente (comparación española sin mayúsculas ni acentos) tras arrastrarlas a una escena; extremos de página sincronizados al perder el foco.

Los ajustes visuales anteriores (gestor unificado, chips, paneles laterales y la barra RTF de Mobile) están en el historial de Git de este archivo; sus reglas vigentes, en `docs/GUIA_ESTILOS.md`.
