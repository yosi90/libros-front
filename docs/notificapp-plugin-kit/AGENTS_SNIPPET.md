# Instrucciones para los `AGENTS.md` de otros proyectos

Copia **uno** de estos bloques al `AGENTS.md` del repositorio correspondiente. Ambos ordenan añadir `/plugin-kit/` al `.gitignore` raíz en cuanto se copie la carpeta. La credencial de agente se configura por equipo y fuera del repositorio; copiar las instrucciones no la instala.

## API de Libros, Fichas u otra API que guarda solicitudes

> En cuanto se copie `plugin-kit/` a la raíz, añade `/plugin-kit/` al `.gitignore` y comprueba que Git lo ignore. Copia el ejemplo a `notificapp-plugin/` fuera del kit y versiona allí el manifiesto y la interfaz propios.
> Lee `plugin-kit/README.md`, `plugin-kit/PROJECT_PLUGIN.md` y `plugin-kit/AGENT_NOTIFICATIONS.md`. Este repositorio es responsable de dos vías independientes de Notificapp. **Vía proyecto:** crea y mantiene el paquete `manifest.json` + `ui/index.html` para el panel móvil, los endpoints declarados y los avisos de solicitudes nuevas después de confirmar la transacción. Conserva un `externalId` estable para los reintentos. Si es Libros o Fichas, usa el ID y el tipo de aviso ya registrados que indica `PROJECT_PLUGIN.md`. Genera el primer ZIP y entrégalo al propietario junto con el código fuente para revisión; no lo instales ni publiques directamente. No incluyas secretos en el ZIP o Git. **Vía agente:** tus propias respuestas finales y preguntas se envían al espacio «Agentes» mediante `agent_notify.py` y la credencial privada de este equipo, nunca con el token del plugin. Usa `--title` para indicar agente, proyecto y situación, y envía como cuerpo el texto completo y exacto. Antes de preguntar al propietario, envía `agent_question`; para un cierre sin hook comprobado, envía `agent_finished` antes de tu respuesta final. Comprueba el resultado y evita duplicar un aviso ya enviado por un hook.
> Después de que el propietario apruebe e instale la primera versión y active las actualizaciones remotas para este espacio, sigue el apartado «Revisión inicial y actualizaciones» de `PROJECT_PLUGIN.md`: si compartes servidor con Notificapp, copia la credencial vigente de su archivo privado a `.runtime/notificapp-update.token`; si estás en otro servidor, recíbela por un canal privado. Comprueba que Git la ignore y publica versiones posteriores con `pack.py` y `publish.py`. La activación en la APK ya registra la credencial; no crees otra identidad ni uses el token emisor. Cada versión debe aumentar y conservar `eventKinds`, `agents`, `api.baseUrl` y `api.actions`. Si necesitas ampliar esos permisos o rutas, entrega el ZIP para revisión local. Si el permiso está apagado o falta el archivo, prepara el paquete y comunica ese estado sin publicar ni mostrar la credencial.

## Frontend web de Libros, Fichas u otro proyecto

> En cuanto se copie `plugin-kit/` a la raíz, añade `/plugin-kit/` al `.gitignore` y comprueba que Git lo ignore.
> Lee `plugin-kit/README.md` y `plugin-kit/AGENT_NOTIFICATIONS.md`. Este repositorio solo necesita la vía de **avisos de agente**: Codex o Claude pueden enviar sus respuestas finales y preguntas al espacio «Agentes» con `agent_notify.py` y la credencial privada del equipo. Usa `--title` para indicar agente, frontend y situación; conserva como cuerpo la respuesta o pregunta completa y exacta. Antes de preguntar al propietario, envía `agent_question`; para un cierre sin hook comprobado, envía `agent_finished` antes de tu respuesta final. Comprueba el resultado y evita duplicados si un hook ya publicó el turno. La API del proyecto es quien crea el plugin móvil y publica los avisos de solicitudes confirmadas; no crees otro plugin ni publiques esos mismos avisos desde este frontend. No pongas credenciales en Git, en el ZIP o en tus respuestas.

Los dos bloques requieren que el propietario configure primero el emisor de agente de ese equipo. Si falta esa configuración, prepara la integración y comunica qué credencial privada falta; no inventes un token ni reutilices la del plugin.
